# fix: Make the 11 skipped E2E tests pass

- **Release tag:** `v0.0.49`
- **Source PR:** [#249](https://github.com/mpaulosky/IssueManager/pull/249)

## PR description

Closes #246

### Summary

The 11 tests skipped as `Fails: #246` now run and pass. Two of the failures were app bugs, two were test bugs.

**App fixes**

```diff
 AddAuth0 (src/Web/Extensions/AuthExtensions.cs)
+  CookieAuthenticationOptions
+    LoginPath        = /auth/login     (was the default /Account/Login, which doesn't exist)
+    ReturnUrlParameter = returnUrl
+    AccessDeniedPath = /not-authorized (was the default /Account/AccessDenied, which doesn't exist)
```

```diff
 <Home>
   <a href="/issues">View Issues</a>
+  <AuthorizeView><Authorized>
     <a href="/issues/create">New Issue</a>
+  </Authorized></AuthorizeView>
```

**Test fixes**

- Menu checks are scoped to `nav[aria-label='Main navigation']`. `a[href='/issues']` and `a[href='/issues/create']` also matched the home page's buttons, so Playwright's strict mode rejected them. The signed-out New Issue check stays page-wide, so it covers the home page too.
- The admin tests requested `{WebUrl}/issues/create` with `WebUrl` already ending in `/`, so they hit `//issues/create`, which no route matched. They now trim the slash like the other E2E tests.

| Test | Cause | Fix |
| --- | --- | --- |
| `Unauthenticated_ProtectedRouteRedirectsToLogin`, `User_ProtectedRouteRedirectsAfterLogout` | Redirect to `/Account/Login` | Cookie `LoginPath` |
| `Unauthenticated_DoesNotSeeNewIssueLink` | Home button shown to everyone | `<AuthorizeView>` |
| `User_/Author_SeesAppropriateMenuItems`, `User_SeesNewIssueLinkAfterLogin`, `Author_NewIssueLinkHiddenAfterLogout` | Ambiguous selectors | Scope to main nav |
| `Admin_CanCreateAndViewIssue`, `Admin_CanNavigateToCreateIssuePage`, `Admin_CanFilterIssuesPage`, `Admin_CanViewCategoriesForArchive` | `//` in URL | Trim trailing slash |
