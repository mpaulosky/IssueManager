# fix: Publish each Sandcastle issue as its own PR, and fix the other #276 review findings

- **Release tag:** `v0.0.67`
- **Source PR:** [#285](https://github.com/mpaulosky/IssueManager/pull/285)

## PR description

### Why

This addresses the Claude Review findings on #276, the Sandcastle setup. Sandcastle used to merge finished branches into the local branch with a merger agent, and that agent closed issues before their work reached `main`. Its merge decision came from the commits made in the current round, so a branch finished in an earlier round was never merged. The sandbox also held a GitHub token while reading issue text from anyone. Other findings: the root lockfile hid its dependencies from Dependabot, bug branches were named `hotfix/`, the Sandcastle tests never ran automatically, and commits used a `RALPH:` prefix.

The new design follows mpaulosky/Articles#308, minus the problems that PR's own review found.

### What changed

- **One draft PR per issue, one round per run, and no merger** (`lib/build.mts`, `main.mts`). For each issue, the implementer works, the host runs `.sandcastle/check.sh`, and then the reviewer ends with a <code>&#60;verdict&#62;</code> (`lib/verdict.mts`). An approved branch's checked commit is pushed and gets a draft PR with `Fixes #n`. Anything else gets a comment on the issue and isn't pushed. `merge-prompt.md` is gone, and nothing closes issues.
- **Decides from the branch, not the round.** Whether there's work to publish comes from <code>git rev&#45;list &#45;&#45;count &#60;base&#62;&#46;&#46;&#60;HEAD&#62;</code>. Nothing merges during a run, so a run is a single round. The planner also sees issues whose PRs are open, as open and blocking, but can't pick them.
- **No GitHub access in the sandbox.** The host reads issues with its own `gh` auth. Only issues and comments from the owner, members and collaborators reach the agents, through their prompts (`lib/github.mts`, `lib/prompts.mts`). `main.mts` won't start if `.sandcastle/.env` sets `GH_TOKEN` or `GITHUB_TOKEN`. The image no longer installs `gh`.
- **What this version does that Articles#308 doesn't:**
  - The host never runs git against config the agents can write (`lib/git.mts`). Fetches, ls-remote and pushes run in a host-only bare repo under `~/.cache/sandcastle`, whose origin comes from `config.mts`. Objects move by local fetches. The few commands that remain in the clone turn off hooks, fsmonitor, alternate-refs commands, replace refs, auto gc and every transport but local files. Host-repo git never prompts, and the run checks for a github.com HTTPS credential (`gh auth setup-git`) before any agent starts. `gh` runs with `-R` from a temp folder. No hook runs, so the Docker suites are left to CI.
  - `origin/main` is merged into the branch inside the sandbox before the implementer starts (if that conflicts, the prompt asks the implementer to merge it). The host won't publish a branch that doesn't contain the base commit.
  - It pushes exactly the commit it checked, from the host repo, without force. An existing local branch that's behind origin's is fast-forwarded first.
  - It checks again whenever HEAD moved after the reviewer, even if the reviewer reported no commits, and stops if an agent left the worktree on another branch.
  - PRs from forks (`isCrossRepository`) neither hold an issue back nor pass for its PR.
  - If the planner names an issue twice, it's built once.
  - The PR title loses any trailing space, and the reviewer's summary is fenced in the PR body and issue comments, so GitHub doesn't act on its closing keywords or mentions.
- **Keeps #281's check.** Each round pins the fetched `origin/main` commit and its `check.sh` (`baseCheck`). Every host git decision, new branch and prompt uses that commit, not the ref, since agents share the clone's refs. A branch that changes the check's own files still hands its issue to a person with `sandcastle:needs-human`, and such issues are left out of the plan.
- **Branch names** (`lib/branches.mts`). Bugs get <code>fix&#47;&#123;n&#125;&#45;&#8230;</code>, not `hotfix/`. Existing `fix/` and `hotfix/` branches are reused, whether on origin or only local.
- **Commits** use <code>&#60;type&#62;&#40;&#60;scope&#62;&#41;&#58; &#60;Summary&#62;</code> with `Refs #n`, not `RALPH:`.
- **Lockfile.** A root `pnpm-workspace.yaml` with `pmOnFail: ignore` (as `src/Web` has), and `pnpm-lock.yaml` regenerated as a single document.
- **Tests run automatically.** `test:sandcastle` now type-checks first (`.sandcastle/tsconfig.json`, TypeScript, `@types/node`, and `@standard-schema/spec` so Sandcastle's output types resolve). `check.sh` runs it, as #286 set up, and `.github/ci/gate-checks.sh` (pre-push) and `.github/ci/prepare.sh` (CI's Build Solution) run it when a branch changes Sandcastle, the root Node packages, `pnpm-workspace.yaml`, or the branch-name and PR-title scripts. #286's `lib/rounds.mts` served the merger loop this PR removes, so it's gone.

One finding was rejected after checking. It said an issue title containing `` !`cmd` `` would be run when the prompt is built. In `@ai-hero/sandcastle` 0.12.0, `substitutePromptArgs` marks the prompt file's own `` !`…` `` blocks before it fills in <code>&#123;&#123;&#8230;&#125;&#125;</code>, and only marked blocks are run. I confirmed this with a real `run()` against a test prompt: the title's command was passed on as text and never ran. Either way, the sandbox no longer has a token, and untrusted authors' text is dropped.

### Verification

- `pnpm run test:sandcastle`: the type check is clean and 82 tests pass. New tests cover the pipeline (an earlier round's finished branch is published, HEAD moving after the reviewer, the wrong branch, a branch behind main, a rejected verdict, a branch that changes the check's files), and real-git tests show the push sends the checked commit from the host repo, even after an agent rewrites the clone's origin, runs none of the clone's hooks or a planted `core.alternateRefsCommand`, refuses to overwrite commits on origin, and syncs stale local branches.
- `pnpm install --frozen-lockfile` passes, and the lockfile has no `---` document separators.
- `shellcheck` and markdownlint are clean. The pre-push gate passed, including the Docker suites.
- Not run end to end against Docker and GitHub.
