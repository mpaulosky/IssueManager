# fix(Tests): Give the E2E host fake Auth0 settings when none are set

- **Release tag:** `v0.0.64`
- **Source PR:** [#282](https://github.com/mpaulosky/IssueManager/pull/282)

## PR description

### Why

Dependabot PR #280 fails **Tests: AppHost.Tests.E2E**: every Playwright test fails in `PlaywrightFixture.InitializeAsync` with `Stopped waiting for resource 'WebApp' to become healthy because it failed to start.` The bumps aren't the cause. Dependabot runs get no Actions secrets, so `TEST_ENV` is empty (`No TEST_ENV secret; no test secrets exported.`) and nothing configures Auth0. Both services then crash at startup (exit 134):

- `api-service`: `System.InvalidOperationException: Auth0 configuration is missing (Auth0:Domain and/or Auth0:Audience).`
- `WebApp`: `System.InvalidOperationException: Unable to resolve service for type 'Microsoft.AspNetCore.Authentication.IAuthenticationSchemeProvider' while attempting to activate 'Microsoft.AspNetCore.Authentication.AuthenticationMiddleware'.` (`AddAuth0` skips `AddAuthentication` when Auth0 isn't set, but `UseAuthentication` still runs.)

#280 is the first NuGet Dependabot PR since #247 made the fixture fail rather than skip, so every Dependabot NuGet PR would hit this.

### What changed

When neither user secrets nor environment variables set `Auth0:Domain`, `PlaywrightFixture` gives `WebApp` and `api-service` fake Auth0 settings (an `.invalid` domain). The host starts, the tests that log in skip without credentials as they already do, and the rest run. This is the fallback ci.yml's `TEST_ENV` comment expects of fixtures. When Auth0 is configured (locally, or CI on non-Dependabot PRs), nothing changes.

### Verification

- Reproduced the CI failure locally: fresh `HOME` with a newly made dev cert, Release, no secrets. 36 failed, and the resource logs showed the two exceptions above.
- With the fix, in the same environment: 54 total, 25 passed, 29 skipped (the login tests), 0 failed.
- With real Auth0 user secrets: 54/54 passed. The pre-push gate passed (on its second run: the first hit flaky real-Auth0 logout tests, which this change doesn't touch).
