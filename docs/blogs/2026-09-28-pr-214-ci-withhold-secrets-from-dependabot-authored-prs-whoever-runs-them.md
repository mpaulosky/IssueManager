## ci: Withhold secrets from Dependabot-authored PRs, whoever runs them

- **Release tag:** `v0.0.36`
- **Source PR:** [#214](https://github.com/mpaulosky/IssueManager/pull/214)

### PR description

Follow-up to the Dependabot test changes. Copilot pointed this out on mpaulosky/Blazor-Server#106.

The Playwright exclusion keyed on `github.actor`, and the workflow-level Auth0 env was set for every run. When a maintainer re-ran, reopened or updated a Dependabot PR, the run's actor was the maintainer. That run then got the real Auth0 credentials while running unreviewed dependency code: E2E ran, and restore, build and every test job could read the env. A branch update is enough to trigger this, and the auto-merge flow does those routinely.

- Every workflow-level secret now resolves to an empty string on a `dependabot/*` branch (`startsWith(github.head_ref || github.ref_name, 'dependabot/')`), whatever triggered the run. That includes re-runs, reopens, branch updates and manual dispatches.
- Test discovery leaves the Playwright projects out on those branches. They run on `main` after merge.
- Push runs on `main` are unaffected.
- The "Publish test results" step still keys on `github.actor`, because the actor decides whether the run's token can write.

Validation: no new `actionlint` or `yamllint` findings in the changed file, and the pre-push hook passed.
