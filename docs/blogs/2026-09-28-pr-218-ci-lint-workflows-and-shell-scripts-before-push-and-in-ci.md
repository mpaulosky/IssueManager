## ci: Lint workflows and shell scripts before push and in CI

- **Release tag:** `v0.0.38`
- **Source PR:** [#218](https://github.com/mpaulosky/IssueManager/pull/218)

### PR description

Brings over the workflow and shell lint that atelier-store and TicketManager run (mpaulosky/TicketManager#69), and fixes everything it found on `main`.

## New checks

- **`lint-actions.yml`** runs `actionlint`, `zizmor` (fails on medium or above) and `shellcheck`, all pinned.
- **`scripts/gate.sh`**, run by the pre-push hook, lints the changed Markdown, YAML, workflow and shell files, builds the solution, then runs each test project.
- **`pre-push`** checks the refs actually being pushed, and refuses a dirty working tree or a commit that isn't checked out. Branch naming rules are unchanged.

## Fixes to what the linters found

- **Every action is pinned to a commit SHA.**
- **`ci.yml`:**
  - The default token is now read-only; only the report job can write.
  - Matrix values go through `env:` instead of being interpolated into scripts.
  - Checkouts no longer keep their credentials.
- **`code-metrics.yml`:**
  - `if: ${{ … }} == 'true'` was always true.
  - The dispatch reason was interpolated straight into a shell script.
  - Its push and PR triggers never fired, because a `paths:` filter with only `!` patterns matches nothing. It's now explicitly manual-only.
- **Workflows copied as-is** from TicketManager: `dependabot-auto-merge`, `label-enforce`, `lint-markdown`, `lint-yaml`, `pr-automerge` and `sync-readme` were identical apart from these fixes.

## Builds no longer dirty the tree

The new dirty-tree check needs a build that doesn't rewrite tracked files, and this one did:

- `Web.csproj` ran `npm install`, which rewrote the tab-indented `package-lock.json` in npm's two-space style.
- `app.css` was still the Tailwind 4.2.1 build after #210 raised Tailwind to 4.3.3.

The build now runs `npm ci`. The lockfile is committed in npm's format, with an `.editorconfig` exception, and `app.css` is regenerated. A second build leaves both files unchanged.

## Squad tooling removed

Squad isn't used here, so `squad-branch-worktree-cleanup.yml` and the cleanup script are gone.

The PR auto-merge decision logic used to live in the same folder. It moves to `.github/scripts/automerge-decision.mjs`, and `pr-automerge.yml` now reads it from there. A new `automerge-tests.yml` replaces `squad-scripts-test.yml` and runs its 11 tests, which all pass.

## Validation

- `actionlint`, `zizmor` (online audits included), `yamllint` and `shellcheck` are clean.
- The pre-push gate passed (build and every test project), and the working tree was still clean afterwards.

**Follow-up after merge:** make `actionlint`, `zizmor` and `shellcheck` required in the `main-rules` ruleset.
