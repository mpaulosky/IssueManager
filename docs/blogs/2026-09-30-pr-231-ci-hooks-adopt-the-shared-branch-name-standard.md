## ci(hooks): Adopt the shared branch-name standard

- **Release tag:** `v0.0.43`
- **Source PR:** [#231](https://github.com/mpaulosky/IssueManager/pull/231)

### PR description

## Summary

Part 2 of #227, porting mpaulosky/IssueTracker#182 and #186: the branch-name standard every repo now shares.

| Pattern | Use |
| --- | --- |
| `feature/{issue}-{slug}` | New behaviour |
| `fix/{issue}-{slug}` | A bug fix |
| `hotfix/{issue}-{slug}` | An urgent fix |
| `chore/{slug}` | Work without an issue |

- **Issue numbers:** `feature/`, `fix/` and `hotfix/` now name their issue. The hook used to accept any slug.
- **`chore/` slugs start with a letter,** so `chore/7-cleanup` can't pass for an issue-linked name.
- The hook's message lists all four patterns.
- **`docs/CONTRIBUTING.md`** now lists the standard, and says to branch from and open PRs against `main`. It used to say `develop`, a branch this repo doesn't have.

## Testing

- New hook cases: each accepted prefix runs the gate (including slugs with digits). Each retired or malformed name is refused: `squad/`, `sprint/`, a prefix without an issue number, an uppercase letter in an otherwise valid name (`feature/9-Upper`, `chore/tidy-Up`), and a `chore/` slug starting with a digit.
- Against the old hook, four of the new cases fail: the three prefixes without an issue number, and `chore/7-cleanup`. With the change: 48 passed, 0 failed.
- `shellcheck` is clean. This branch went through the new pre-commit hook, which linted the staged `docs/CONTRIBUTING.md`, and through the pre-push gate.
