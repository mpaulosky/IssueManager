# ci: Standardize on the repo-ci-baseline Template

- **Release tag:** `v0.0.47`
- **Source PR:** [#241](https://github.com/mpaulosky/IssueManager/pull/241)

## PR description

### Why

TicketManager, IssueTracker, atelier-store and Blazor-Server already run the shared CI, release and git-hook Baseline, kept as a Template in `mpaulosky/dotfiles`.
One Apply of the Template brings IssueManager onto it, and replaces the eight separate PRs #227 planned.
It also turns Markdown lint back on: `.markdownlint.json` was `{"default": false}`, so the lint passed while checking nothing (#229).

### What changed

**Template Apply** (`chore: apply repo-ci-baseline Template`, the script's output alone):

- Owned files: the git hooks, `scripts/gate.sh`, the CI, lint, release and auto-merge workflows, and the release scripts with their tests.
  Also `docs/PROCESS.md`, the PR template, `global.json`, `.gitignore`, `.editorconfig` and the lint configs.
- Releases follow merge order through a queue, and a missed release is retried.
  Docs-only PRs skip the build and tests (`detect_changes.py` replaces `dorny/paths-filter`).
- A PR auto-merges only after Copilot has reviewed its head and every thread is resolved, until Copilot's three-round review cap.
  Past the cap, the latest head needs no new Copilot review and Copilot's open threads no longer block; other reviewers' threads still do.
- Branch names and PR titles are checked by the hooks and by CI (**Branch name**, **PR title**).

**Adapting IssueManager to it:**

- `.github/ci/prepare.sh` enables pnpm through Corepack for the Tailwind build.
  The Auth0 values the tests need now come from the `TEST_ENV` secret instead of per-variable secrets in `ci.yml`.
- `dependabot.yml` takes the Seed's commit-message blocks and a Testcontainers group, and keeps the npm ecosystem and the Microsoft.OpenApi ignore.
- Every test project moves from `xunit.runner.visualstudio` to `xunit.v3.mtp-v2` on Microsoft Testing Platform, with the Microsoft.Testing pins raised to 2.4.0.
- The gate and CI build with `-warnaserror`, which overrode `CodeAnalysisTreatWarningsAsErrors=false`.
  `AnalysisMode=all` therefore turned the 1,488 analyzer warnings `main` carried into errors.
  The default analysis mode reports none; raising it again is follow-up work.
  AppHost suppresses ASPIRE010, as TicketManager and IssueTracker do.
- The analyzer overrides from the old root `.editorconfig` move to `tests/.editorconfig` and `src/.editorconfig`.
  The generated `app.css` is ignored by `src/Web/.gitignore`, because the root files are Owned by the Template.
- Markdown lint applies `.markdownlint-cli2.jsonc` to every file: `--fix` took 1,027 findings to 184, which were fixed by hand.
- The Seed `docs/SECURITY.md` the Apply wrote is deleted again: it is the other project's policy #237 removed.
- Deleted: `.markdownlint.json`, `automerge-decision.mjs` with its test and `automerge-tests.yml`, `sync-readme.yml`, `label-enforce.yml` and the duplicate `.copilot-commit-message-instructions.md`.
- The v0.0.9 to v0.0.19 release posts are renamed to `<date>-pr-<n>-release-vX.md`, so the release workflow finds them and doesn't write them again.
- `docs/index.html` carries the markers the release workflow fills with the Releases table and post cards, in place of the script that refreshed its tables from the GitHub API.
- `CONTRIBUTING.md` and the README point the process at `docs/PROCESS.md`.

The repo's GitHub settings were brought to the standard with `github-settings.sh --fix`.
The `main-rules` ruleset now allows squash merges only and requires `markdownlint` and `yamllint` in place of `Analyze (csharp)`.
The labels `semver:minor`, `semver:major`, `docs-only` and `sandcastle:needs-human` were added.
