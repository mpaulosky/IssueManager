## chore(web): Stop committing the generated app.css

- **Release tag:** `v0.0.39`
- **Source PR:** [#220](https://github.com/mpaulosky/IssueManager/pull/220)

### PR description

Every Tailwind bump from Dependabot left the committed `src/Web/wwwroot/css/app.css` stale. The lockfile moved on, but the CSS in git was still the old build (#218 fixed the latest case by hand). Each local build then regenerated the file and dirtied the tree, which the pre-push gate refuses. CI never noticed, because it regenerates the file too.

The build already produces `app.css` on every run, CI included. So it's now untracked and ignored, as in atelier-store and mpaulosky/TicketManager#92.

## Keeping `@Assets["css/app.css"]` working on a clean checkout

`wwwroot/**` is collected when the project first loads, before `app.css` exists. So `BuildTailwindCSS` now adds the file to `@(Content)` right after generating it. Without that, a clean build left `css/app.css` out of the static-asset manifest; I checked, and with only the untracking the manifest had no entry for it.

## Validation

- A build with no `bin/`, `obj/`, `node_modules/` or `app.css` now lists `css/app.css` in `staticwebassets.build.json`.
- The pre-push gate passed (build and every test project).

**For existing clones:** after pulling, git deletes the local `app.css`, and the next build recreates it.
