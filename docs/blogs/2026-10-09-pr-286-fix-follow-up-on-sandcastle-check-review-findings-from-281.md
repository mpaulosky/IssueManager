# fix: Follow up on Sandcastle check review findings from #281

- **Release tag:** `v0.0.66`

## PR description

### Why

#281 merged through PR Auto-Merge's review cap with four Claude Review threads still open. This PR fixes them.

### What changed

- **Checked branches merge without new commits** (`main.mts`): a branch now goes to the merge when the commit the host checked is ahead of the base (<code>git rev&#45;list &#45;&#45;count &#60;base&#62;&#46;&#46;&#60;checked&#62;</code>), not when the current round made commits. Earlier work that failed the check then (a flaky test, say) and passes now still merges, and it no longer counts as "no progress", which used to stop the run.
- **Git warnings aren't read as results** (`lib/check.mts`): `git diff` and `git status` drop `2>&1` and parse only stdout. A warning on stderr, such as "multiple merge bases", no longer reads as a changed check file or a dirty worktree. When a command fails, its stderr goes into the failure message. A new test covers this.
- **The Sandcastle tests run in the gate and CI**: `.github/ci/gate-checks.sh` (pre-push) and `.github/ci/prepare.sh build` (CI's Build Solution job) run `pnpm run test:sandcastle` when `.sandcastle/`, `package.json` or `pnpm-lock.yaml` change, as Articles does.
- **Merge-phase gap documented**: the host doesn't re-check the merged result. `main.mts` now records that as an accepted gap: the next round's checks run on top of the merge, and the pre-push gate runs everything before a push.
