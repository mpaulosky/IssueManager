## build: switch the web project from npm to pnpm

- **Release tag:** `v0.0.40`
- **Source PR:** [#222](https://github.com/mpaulosky/IssueManager/pull/222)

### PR description

<!-- ccr-projects-attribution: {"github_login":"mpaulosky"} -->
_Requested by **Matthew** · [project thread](https://claude.ai/code/project/chan_01M4TRjuaTvMLM1jqeNd9KNs?thread=cmsg_01M4TRjuaTvMLM1jqeNd9KNsBqvSH7Zyjxovd4Kr4rap1i)_

Before: the Tailwind CLI in `src/Web` was installed and run with npm (`npm ci`, `npx @tailwindcss/cli`), relying on the npm that ships on the runner. The gate script and the Copilot MCP config used `npx`.

After: `src/Web` uses pnpm 12.6.0, pinned through `packageManager`, with a committed `pnpm-lock.yaml`, and `npm install` there is refused (`engines.npm` + `engine-strict`), matching atelier-store and TicketManager.

The lockfile was converted with `pnpm import`, so every resolved version is unchanged (Tailwind stays at 4.3.3).

How:
- `package.json`: scripts call the `tailwindcss` bin directly; adds `packageManager` and the npm engine block. New `.npmrc` and `pnpm-workspace.yaml` (the `@parcel/watcher` install script isn't needed, so it stays off).
- `Web.csproj`: `pnpm install --frozen-lockfile` when `node_modules` is missing, then `pnpm run build:css`.
- `ci.yml` (build and test jobs) and `codeql-analysis.yml`: a SHA-pinned `pnpm/action-setup` step that reads the version from `src/Web/package.json`.
- `scripts/gate.sh`, pre-commit hint, `copilot-instructions.md`, `.github/mcp-config.json`: `npx` → `pnpm dlx`.
- `.editorconfig`: the `package-lock.json` exception goes with the file.
- Dependabot keeps `package-ecosystem: "npm"`, which covers pnpm lockfiles.

Verified locally from a clean tree: `scripts/gate.sh` passed (YAML, actionlint, zizmor, shellcheck on the changed files, Release build, and all seven test projects including API integration and AppHost E2E). A second build leaves the tree clean. The same gate passed on `main` beforehand.
