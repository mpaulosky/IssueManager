# chore: Give Sandcastle a Docker-free check script

- **Release tag:** `v0.0.65`
- **Source PR:** [#281](https://github.com/mpaulosky/IssueManager/pull/281)

## PR description

### Why

The Sandcastle sandbox has no Docker, on purpose: mounting the host's Docker socket would give its agents, who read public issue content, root on the host. The prompts told agents to run `scripts/gate.sh` and, when it failed "for want of Docker", to rerun the other test projects one by one. That made the outcome depend on the agent judging why the gate failed. This PR replaces it with a deterministic check, following mpaulosky/Articles#308.

### What changed

- **`.sandcastle/check.sh`** (new) runs, in order:
  - Markdown lint of the changed files. It is the only gate lint the image can run: yamllint, actionlint, zizmor and shellcheck aren't in the image, and their fallbacks need Docker.
  - `.github/ci/gate-checks.sh`.
  - A Release build with `-warnaserror`.
  - `dotnet test` on every project that `discover_tests.py --list` finds, except any whose `.csproj` references `Testcontainers*` or `Aspire.Hosting.Testing`. Today that skips `tests/Api.Tests.Integration` and `tests/AppHost.Tests.E2E`.
  - `pnpm run test:sandcastle`.
- **`main.mts`**: the host runs the check in the sandbox (new `lib/check.mts`) after the implementer reports completion, and again if the reviewer committed. An issue counts complete only when the check exits 0 and the worktree is clean. `lib/check.test.mts` covers this.
- **Prompts** (implement, review, merge), **`CODING_STANDARDS.md`** and **Dockerfile** comments now point at `check.sh`. They say plainly that the Docker suites run in the host's pre-push gate and in CI.
- **`.gitignore`**: adds `.pnpm-store/`. pnpm puts its store at the repo root inside the sandbox, because the bind-mounted worktree is on a different file system from the home folder. That leftover store would fail the clean-worktree check and the pre-push gate.

### Verification

- Built `.sandcastle/Dockerfile` and ran `.sandcastle/check.sh` inside it against this branch, with no Docker socket mounted. It passed: 5 of 7 test projects ran and passed, the Integration and E2E projects were skipped as needing Docker, and the Sandcastle tests passed (17).
- The host pre-push gate (full suite, including the Docker suites) passed.
- `shellcheck .sandcastle/check.sh` is clean.
